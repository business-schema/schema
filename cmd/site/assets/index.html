A shared definition of the things a business runs on.

Every system has its own idea of a customer. Business Schema defines it once, in the open: the properties it has, which of them are personal data, and how to tell that two systems are describing the same one.

An entity has its own identity and life. A value type is a reusable shape held inside an entity, such as an address on a customer.

Using the schema

Read a definition

Each type is published as a page for people and a JSON document for software. The whole release is one catalogue.

curl https://business-schema.org/customer.json
curl https://business-schema.org/catalogue.json

Shape your records to match

A record is a JSON object keyed by the type's property keys. Every entity has an id and can link to IDs in other systems through external_references. Value types nest; collections can be keyed by labels, lists, or lists under each label.

Load it from Go

The Go module carries the definitions it was released with, so upgrading is a deliberate change to your dependencies.

go get github.com/business-schema/schema

catalogue, err := schema.Load()
customer, _ := catalogue.Entity("customer")

What a definition tells you

Shape
Each property's type and format, such as a date, a country code or a nested value type.
Personal data
Which properties identify a person, and which should stay masked until someone asks to see them.
Matching
Which property identifies the same record in another system, and when two values count as equal.
Life
For entities: the statuses a record moves through, the actions that change it and the events those raise.
Equivalents
Where a term matches one in schema.org, the definition links to it.

Status

This is a draft. Definitions may change incompatibly until version 1.0. From 1.0, a change within a major version only adds.
